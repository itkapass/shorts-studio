Privacy Policy

How Shorts Studio handles Google user data.

HomeTerms of Service

Last updated: 30 August 2026

1. Who this covers

Shorts Studio is self-hosted software. The person who installs and runs it (the "operator") is the only user. This policy describes how the software handles data belonging to that operator's own Google Account.

2. What Google user data is accessed

The application requests a single OAuth scope:

  • https://www.googleapis.com/auth/youtube.upload — permission to upload video files to the operator's YouTube channel.

This scope is used exclusively to call the YouTube Data API videos.insert endpoint. No other Google API is called and no other scope is requested.

3. How that data is used

The access token obtained through this scope is used for one action: uploading a video file, together with its title, description and tags, to the operator's own YouTube channel, after the operator has approved that video for publishing.

4. How credentials are stored

  • The OAuth client ID, client secret and refresh token are stored as encrypted repository secrets in the operator's own GitHub account, or in a local environment file on the operator's own machine.
  • Credentials are never written to a database, never logged, and never included in any file the software produces.
  • Credentials are read into memory only for the duration of an upload and are not persisted anywhere else.

5. Data sharing

No Google user data is shared with any third party. The software has no analytics, no telemetry, no crash reporting, and no external service that receives account information. It communicates with the following services, none of which receive Google account credentials or Google user data:

  • Google Gemini API — receives only topic text for script writing.
  • Pexels API — receives only stock-footage search keywords.
  • Supabase — stores video metadata (titles, descriptions, status) belonging to the operator.
  • Cloudflare R2 or Supabase Storage — stores the rendered video files temporarily.

6. Data retention and deletion

  • Rendered video files are deleted from storage immediately after a video is published, rejected, or exported.
  • Video metadata is retained in the operator's own database until the operator deletes it.
  • The operator can revoke this application's access at any time at myaccount.google.com/permissions. Doing so immediately and permanently ends all access.
  • Deleting the stored refresh token also ends all access.

7. Limited Use disclosure

Shorts Studio's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Specifically:

  • Google user data is used only to provide the video-upload feature described above.
  • Google user data is not transferred to any third party except as required to provide that feature.
  • Google user data is not used for advertising purposes.
  • No human reads Google user data, except as required for security purposes or to comply with applicable law.

8. Children

This software is not directed at children and is not intended for use by anyone under 18.

9. Changes

Any change to this policy will be published on this page with an updated date above.

10. Contact

Questions about this policy can be sent to the developer contact email listed on the OAuth consent screen for this application.
